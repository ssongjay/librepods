# LibrePods My Mac 0.1.0

Mac과 Galaxy에서 새 재생을 시작한 쪽으로 AirPods 연결을 넘기기 위한 메뉴 막대 앱이에요. 재생이 멈춰도 이전 기기로 돌아가지 않고, 다른 기기에서 새 재생을 시작할 때까지 최근 요청 기기를 유지해요.

## 필요한 환경

- macOS 14.2 이상
- macOS Bluetooth 설정에 미리 등록된 AirPods
- Mac 연동 기능이 포함된 Android용 LibrePods My 0.2.0 이상

## 빌드와 설치

Xcode가 설치된 Mac에서 다음 명령을 실행해요. 외부 패키지를 받지 않고 macOS 시스템 프레임워크만 사용해요.

```sh
cd macos
./build-app.sh "$HOME/Desktop/LibrePods-My-Mac"
```

생성된 `LibrePods My.app`을 응용 프로그램 폴더로 옮긴 뒤 열어요. 앱은 로컬 ad-hoc 서명이므로 macOS가 처음 실행을 확인하면 Finder에서 앱을 Control-클릭하고 **열기**를 선택해요. macOS 보안 기능 전체를 끄지는 마세요.

## 처음 연결하기

1. Mac Bluetooth 설정에서 AirPods를 먼저 페어링해요.
2. 메뉴 막대의 LibrePods My에서 **설정 열기**를 누르고 사용할 AirPods를 선택해요.
3. **휴대전화 페어링 시작**을 누른 뒤, 휴대전화 LibrePods My에서 Mac을 찾아요.
4. 양쪽에 표시된 16자리 보안 코드(`XXXX-XXXX-XXXX-XXXX`)가 완전히 같을 때만 양쪽에서 확인해요.
5. 연결된 뒤 **새 재생 기기로 자동 전환**을 켜요. 이 설정은 처음에는 꺼져 있어요.

설정에 표시되는 검색 목록 이름은 `LPMy-XXXXXXXX` 형식이에요. Mac 설치 키의 공개 부분에서 만든 안정적인 찾기용 이름이라 잠자기나 재시작 뒤 BLE 주소가 바뀌어도 휴대전화가 등록된 Mac을 다시 찾는 데 사용해요. 이 이름만으로 상대를 신뢰하지 않으며, 자동 재연결도 저장된 공개 키의 암호화 인증을 통과해야 완료돼요.

앱은 한 대의 휴대전화 공개 키만 기억해요. 다른 휴대전화로 바꾸려면 Mac과 휴대전화 양쪽에서 기존 등록을 해제한 뒤 다시 페어링하는 것을 권장해요. 등록 해제 후에도 각 기기의 개인 키는 Keychain/Keystore에 유지돼요.

## 동작과 제한

- Mac에서는 CoreAudio가 알려주는 프로세스별 출력 활성 상태를 주기적으로 확인해 새 재생을 감지해요. 오디오 샘플과 곡 제목은 읽지 않고, 앱 이름이나 프로세스 정보도 표시하거나 휴대전화로 보내지 않아요.
- 앱 시작과 자동 전환 활성화 때만 현재 출력을 기준선으로 저장해요. 새 출력 프로세스는 두 번 연속 확인한 뒤 새 재생으로 처리하고, 기존 프로세스는 두 번 연속 사라져야 종료된 것으로 봐요. 오디오 경로가 바뀌어도 새 프로세스 감지 후보를 지우지 않아요. 기기 간 순서는 Mac에서 처음 관측하거나 수신한 시각으로 비교하며 폴링 해상도는 최대 약 0.25초예요.
- 최근 재생 기기는 마지막으로 **요청된** 기기예요. 실제 전환 성공 여부는 별도 상태 문구로 표시돼요.
- Mac이 휴대전화의 양보 확인을 받지 못하면 연결을 강제로 가져오지 않아요. 휴대전화가 오프라인일 때 Mac의 새 재생은 한 번만 제한적으로 Mac 연결을 요청해요.
- macOS 공개 API로 다른 Mac 앱의 재생을 일괄 정지할 수 없어서, 휴대전화로 넘길 때 Mac 재생 자체를 멈추지는 못해요.
- 일부 앱은 자체 출력 장치를 고정할 수 있어 기본 출력 장치 변경을 따르지 않을 수 있어요.
- 공개 CoreAudio 상태만으로 음악과 짧은 앱 효과음을 완벽하게 구분할 수 없어 일부 효과음이 새 재생으로 감지될 수 있어요.
- 자동 재생, 중지 시 복귀, 시작 시 과거 이벤트 재전송은 하지 않아요.
- 같은 앱에서 약 두 번의 폴링보다 짧게 일시 정지·재생하면 짧은 출력 중단을 경로 변경으로 보고 새 시작으로 구분하지 못할 수 있어요. 이때는 메뉴의 **전환 다시 시도**를 직접 눌러 최근 재생 기기로 다시 요청할 수 있고, 자동 재시도는 하지 않아요.

Mac과 Galaxy, AirPods를 함께 사용하는 실제 양방향 전환은 빌드만으로 검증할 수 없어요. 최초 버전에서는 메뉴 상태와 두 기기의 실제 출력 장치를 함께 확인하며 사용해 주세요.

## 보안 구조

Mac은 CoreBluetooth 주변기기로 동작하고 인터넷 서버를 사용하지 않아요. 첫 페어링은 P-256 ECDH로 세션 키를 만들고 양쪽의 80비트 보안 코드 확인을 거쳐요. 이후 메시지는 매 연결마다 새로 만든 키와 AES-GCM으로 인증·암호화하며, 순서가 어긋나거나 인증에 실패하면 해당 연결을 닫아요. Mac 개인 키는 Keychain에 저장돼요.
